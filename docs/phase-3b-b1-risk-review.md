# Phase 3B-B1 Risk Review — Projectile + Hit Shape Foundation

> Risks to watch for when reviewing Agent A's Phase 3B-B1 PR (projectile
> foundation, Power Shot, Fireball, melee hit shape helper, AoE instant
> placeholder, minimal VFX feedback). **Docs/spec/QA only.** Use alongside
> `docs/phase-3b-b1-pr-review-checklist.md` (what to check) and
> `docs/phase-3b-b1-mobile-test-script.md` (how to test on a phone).

| Risk | What to inspect in PR | How to test | Blocker? |
|---|---|---|---|
| **Projectile tunneling** — fast projectile (Power Shot 650, Fireball 520 speed) passes through the dummy without registering a hit, especially at low frame rates. | Look for how the projectile's hit test is implemented — does it check only the current frame's position, or does it check the path traveled since the last frame (swept/segment check)? | Mobile test script Part 3/4 (fire at the dummy from various distances and angles, including close range); repeat several times to catch frame-rate-dependent misses. | **Yes** — if projectiles can visually miss a dummy they should have hit, core combat feedback is broken. |
| **Projectile multi-hit** — a single projectile applies damage to the dummy more than once (e.g. hit test runs every frame while overlapping before destroy). | Check that the projectile is destroyed/marked-consumed immediately on first hit, before any further per-frame hit checks can run. | Fire Power Shot/Fireball at the dummy and watch the damage number/health bar — should drop by one hit's worth of damage per cast, not multiple. | **Yes** — breaks damage numbers and the armor formula's expected behavior; misleading to players and to future balance work. |
| **Projectile leak** — a projectile that misses is never destroyed (e.g. missing max-range check, or destroy logic only runs on hit). | Check that every projectile has both a hit-destroy path and a max-range-destroy path; check for any early-return that could skip cleanup. | Mobile test script step 9/13 (fire away from the dummy) — confirm the projectile visually disappears after traveling some distance, not staying forever; also run Menu↔Match ×3 cycles and watch for growing slowdown. | **Yes** — accumulating live objects over a session degrades performance and can crash on mobile. |
| **Tween leak** — VFX tweens (hit spark, impact burst, projectile effects) don't destroy their game object on completion. | Check every `tween()` call tied to a VFX sprite has an `onComplete` (or equivalent) that destroys the sprite, not just stops the tween. | Repeatedly trigger hits/impacts (10+ times) and watch for visual "ghost" sprites lingering, or for the game slowing down over time. | **Maybe** — minor leaks may not be immediately visible, but should still be fixed; if it causes visible slowdown or stacking ghost sprites during normal play, treat as **Yes**. |
| **AoE per-frame cost** — an AoE placeholder (if exercised in this PR) is implemented as a per-frame tick/loop instead of a single instant hit-test on cast. | Check the AoE implementation only runs its hit-test once at cast time, not in the scene's update loop for the AoE's `duration`. | If an AoE skill is testable, cast it repeatedly and watch for frame-rate drops, especially on the mobile test viewport. | **Maybe** — if it doesn't cause a visible slowdown on a single dummy, it's a code-quality/future-cost concern (No); if it visibly drops frame rate on mobile, **Yes**. |
| **VFX camera mixup** — a world-space effect (projectile, hit spark, AoE marker) is added to the UI camera (or a UI element added to the main camera), per the dual-camera pattern from Phase 2/`combat-vfx-integration-plan.md`. | Check that new world-space sprites are added to the main camera's render list and `ignore()`-d by the UI camera (and vice versa for any UI feedback touched). | Visually: world effects (projectiles, hit sparks) should move with the game world as the camera follows the player; they should not stay glued to a fixed screen position. Test at multiple viewport sizes (mobile test script Part 6). | **Yes** — breaks visual correctness across viewport sizes and is a known regression pattern from earlier phases. |
| **Mobile visual clutter** — multiple simultaneous effects (hit spark + impact burst + damage number + projectile trail) overwhelm the small mobile viewport or overlap controls. | Check how many VFX objects can be on screen at once for a single cast; check positions relative to the joystick/skill button safe-zone. | Mobile test script Part 6 (915×412 and 800×360) — fire skills repeatedly and watch whether effects ever appear on top of the joystick or skill buttons. | **No** (visual polish) — unless effects actually **block** the joystick/skill buttons from being tapped, in which case treat as the "skill button / joystick regression" risk below (**Yes**). |
| **Skill button / joystick regression** — new projectile/VFX code changes `InputSystem.ts`, `VirtualJoystick.ts`, or `SkillButtons.ts` in a way that breaks the PR #8 multi-touch fix (simultaneous joystick + skill use). | Check whether this PR touches any of the PR #8 input files; if so, check the change doesn't reintroduce the "drag joystick triggers attack" or "one finger cancels the other" bugs fixed in PR #8. | Mobile test script Part 5 (two-finger controls) — hold joystick, tap skill, release each finger independently in different orders. | **Yes** — this is a core mobile-playability regression, not just polish. |
| **Scope creep** — PR includes bot AI, objective/gate/shop/economy logic, multiplayer/networking, or a new player-death/respawn system, beyond "projectile foundation + Power Shot + Fireball + melee hit shape + AoE placeholder + minimal VFX." | Read the full PR diff file list and description; check for new files/systems under those topics, or expanded `TrainingDummy`/`CombatSystem` behavior beyond what `projectile-and-hit-shape-spec.md` describes. | N/A (code/diff review, not a gameplay test). | **Yes** — explicitly out of scope per the Phase 3B-B1 brief. |
| **Accidental asset/docs modification** — PR modifies files under `public/assets/**`, `public/icons/**`, or any of the Phase 3B-B docs (`docs/phase-3b-b-*.md`, `docs/skill-visual-mapping.md`, `docs/projectile-and-hit-shape-spec.md`, `docs/combat-vfx-integration-plan.md`) or this QA gate's docs. | `git diff --name-only` against base — confirm no paths under `public/assets/**`, `public/icons/**`, or the docs listed above appear; also confirm `README.md`, `package.json`, `public/manifest.webmanifest`, `vite.config.ts` are unchanged unless justified. | N/A (file-list review, not a gameplay test). | **Yes** — these paths are explicitly off-limits for the runtime PR per the Phase 3B-B1 brief. |

---

## Summary for reviewers

- **Hard blockers (Yes)**: tunneling, multi-hit, projectile leaks, camera
  mixup, mobile input regression, scope creep, and accidental
  asset/docs/forbidden-file changes. Any one of these means **do not merge**
  until fixed.
- **Conditional (Maybe)**: tween leaks and AoE per-frame cost — fix if
  visible/measurable; otherwise can be tracked as a follow-up if gameplay
  is unaffected.
- **Polish (No)**: minor visual clutter that doesn't block controls or
  gameplay — note for later but not a merge blocker.
